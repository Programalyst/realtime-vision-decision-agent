# Review: 372 ml deterministic run

Source: `runs/deterministic/20260922-200741-907323/annotated.mp4` and
`decisions.jsonl`. Times below are seconds into the recording, not the game's
countdown. This review does not change controller code or configuration.

## Observed result

The video ends at 372 ml and supports the reported zero-bomb-hit run. All 1,095
logged observed-can classifications are `watering_can`; none is disabled or
missing. There are 57 dispatches, 57 command-return events, and no expired-action
events. Median dispatch error is about 1.08 ms. This measures the worker's
dispatch timing, not physical input latency or capture freshness.

Several missed droplets are explicitly marked `skip` before they pass the can.
The planner does not assign a probabilistic danger score and trade it against
water. It rejects trajectories with any predicted bomb collision, then ranks
the remaining branches by predicted droplet count, travel, and available time.
This is a bounded search, not a proof that every skipped droplet was impossible.

## Code reading order

1. `choice_preprocessor.py:17–23` defines the input delay, minimum drag,
   post-catch hold, and command-turnaround allowance.
2. `rolling_planner.py:169–188` builds each collection/escape segment. Lines
   175–176 compute release after a catch as the later of contact plus settling
   and movement completion plus turnaround. Lines 183–184 reject any collision.
3. `rolling_planner.py:79–86` adds input delay to the beginning of each movement.
4. `choice_preprocessor.py:147–162` checks simultaneous vertical and horizontal
   overlap. Bombs use the full mouth/sprite overlap plus margins; collection
   requires the droplet center inside the central 25% of the mouth width.
5. `motion_estimator.py:110–123` expands bomb windows and contracts droplet
   windows by timing uncertainty. The default 40 ms uncertainty affects both
   sides of a close droplet/bomb pair, in addition to the base collision margins.
6. `rolling_planner.py:154–158` creates the explicit skip branch;
   `rolling_planner.py:197–198` ranks routes and retains eight branches.

## Other conservative behaviors worth reviewing

**Bomb-clearance hold.** `rolling_planner.py:177–179` prevents the next row's
command from starting until the current bomb has completely cleared vertically.
Even a next movement whose entire horizontal path stays safely outside the
bomb is delayed. Swept-path safety could permit some of those moves earlier.
That is an algorithmic restriction, not a necessary consequence of the mouth
hitbox. It is a review target; this review does not establish which additional
droplets would be collected by relaxing it.

**Safety hold commitment.** Around 10.99–11.34 s, the log contains synthetic
escape row `-30`, holding the can near x=0.141. Droplets 17 and 18 are on the
right; the score remains 66 ml as they pass around 11.4–11.8 s. The minimum
safety-plan horizon is 350 ms at `deterministic_runtime.py:106`, and its step's
release is the end of that horizon at line 115. Lines 178–181 treat an already
consumed hold as committed. This can prevent opportunistic departure before
the original safety hold expires. It is distinct from merely choosing the
wrong horizontal destination.

**Unsent steps can become part of a committed prefix.** Runtime cutoff comes
from dispatched actions and their release times (`deterministic_runtime.py:178`).
But `rolling_planner.py:122–135` copies all plan steps whose command time falls
before that cutoff, then can recursively extend it through the last such step.
This is broader than preserving only the actual input command already in flight.
In the 9.005 s and 12.359 s snapshots, attempts to force collection of rows 13
and 21 respectively still inherit their old skip steps through this prefix.
Those are not valid forced-collection feasibility results. The prefix behavior
deserves review separately; removing a physical commitment in an offline test
does not prove that changing direction was possible in the live run.

**Strict replacement score.** `deterministic_runtime.py:187–191` replaces a valid
plan only when the proposed route contains more collectible sprites. Equal-count
routes are retained, and single/double droplets have the same score because they
share one detector class. That can preserve an earlier skip even if a different
equal-count route later becomes possible.

**Session timeout starts at J, not gameplay.** At 35.018 s the controller stops
because of its 35 s limit (`deterministic_runtime.py:152–155`). The footage shows
the score changing from 366 to 372 afterward; this may be a catch already in
progress or a delayed score update. It does not prove another missed catch, but
the guard can consume part of a run when J is pressed during the introduction.
It should be reviewed independently of bomb avoidance.

## Suggested human review

Start with the 17.4–17.8 s example and the catch-release calculation. Determine
whether a droplet needs any dwell beyond observed/estimated mouth contact, and
how much. Then inspect bomb-clearance holds and synthetic safety holds: ask
whether the complete next trajectory is safe, rather than requiring the can to
stay at the same destination until a whole interval ends. Preserve swept-path
checks and the zero-hit baseline while testing changes separately.
